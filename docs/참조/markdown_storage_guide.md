# Advanced RAG 및 HITL 기반 마크다운 저장 가이드 & 보완 명세서

본 문서는 **"주제 결정 ➔ 휴먼 아웃라인(결론·질문) 생성 ➔ Advanced RAG 검색 & 채우기(Slot-filling)"** 파이프라인을 거쳐 최종 마크다운(`.md`) 파일로 저장할 때 반드시 포함되어야 할 구조적 보완 사항과 표준 가이드라인을 정의합니다.

---

## 1. 워크플로우 개요 및 포맷 위치

- **시스템 기획서 기준**: `타입 E. 협업 심층 리서치 (Agent Draft 단계)`
- **`md_bank` 포맷 기준**: `포맷 1. 산업·인프라 메가트렌드 아웃라인`의 진화형
- **협업 방식**: **Outline-First HITL (Human-in-the-Loop) Slot-Filling Pipeline**
  - **Human Director**: 주제 발굴 + Core Thesis(결론) + Core Questions(핵심 질문) + 아웃라인 로드맵 정의
  - **Research Agent**: 승인된 아웃라인별 다중 소스 크롤링 + Advanced RAG 검색 + 팩트/해석 채우기
  - **Human Reviewer**: 최종 피드백 코멘트 + 전문가 경험 기반 직접 문단 보강

## 2. 마크다운(.md) 저장 시 필수 보완 5대 핵심 요소

### ① Advanced RAG 출처 투명성 (검색 쿼리 & 인라인 각주)
* **목적**: LLM이 인용한 데이터의 출처를 사후에 추적(Provenance) 가능하도록 보장.
* **보완 내용**:
  * Frontmatter에 `rag_metadata.search_queries` 기록 (사용한 실제 검색어 목록)
  * 본문 핵심 수치 및 인용문에 `[^1]`, `[^2]` 형태의 인라인 각주 필수 매핑
  * 출처 유형을 `1차(공식 공시, IR 트랜스크립트, 학술 논문)`와 `2차(전문 미디어, 리서치 리포트)`로 엄격 구분

### ② 사실(Fact) vs 에이전트 해석(Interpretation)의 엄격한 분리
* **목적**: 검색된 원시 데이터와 AI의 추론·주장이 혼재되는 것을 방지하여 보고서 신뢰도 확보.
* **보완 내용**:
  * 각 아웃라인 서브섹션마다 아래 3분할 슬롯 유지:
    - `- 확인된 사실 (Facts)`: 날짜, 수치, 기준 시점, 원문 팩트
    - `- 에이전트의 해석 (Analysis)`: 팩트로부터 도출된 논리적 시사점
    - `- 미확인 주장 / 한계 (Unverified)`: 교차 검증 미완료 루머 또는 추정치

### ③ 반대 근거(Counter-Evidence)와 반증 조건(Falsification Criteria)
* **목적**: 사람이 설정한 결론에 끼워 맞추는 '확증 편향(Confirmation Bias)' 차단.
* **보완 내용**:
  * RAG 검색 결과 중 Core Thesis와 대치되는 데이터나 비관적 시각을 누락하지 않고 별도 섹션에 수록
  * **반증 조건 명시**: "어떤 수치(예: 수율 X% 미달, 분기 출하량 Y 이하)가 나오면 이 결론을 철회·수정할 것인가"를 사전에 정의

### ④ 휴먼 검토 및 직접 집필 전용 슬롯 (HITL Callout)
* **목적**: 사람이 에이전트의 초안을 검토하고 자신의 통찰을 마크다운 내에 직접 작성할 수 있는 직관적 공간 마련.
* **보완 내용**:
  * 마크다운 Callout 문법(`> [!NOTE] 휴먼 피드백 & 직접 집필란`) 배치
  * 아웃라인 승인 체크박스 및 현장 전문가 시차(Time-lag) 인사이트 작성란 제공

### ⑤ 옵시디언(Obsidian) 양방향 링크 및 지식 네트워크 연결
* **목적**: 단발성 보고서가 아닌, 기존 지식 베이스와 유기적으로 결합되는 지식 화학작용(Knowledge Chemistry) 구현.
* **보완 내용**:
  * `[[기존_문서_파일명]]` 위키링크 자동 연결
  * MOC(Map of Content) 및 연관 태그 체계(`tags: [...]`) 수록
