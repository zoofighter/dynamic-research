> **문서 버전**: v1.0  
> **작성일**: 2026-10-04  
> **상태**: 구현 착수 전 최종 검토 완료

## 1. 개요 및 검토 목적

본 문서는 `langgraph_design_20261004.md`와 `dls_design_20261003.md`를 바탕으로 실제 파이썬 코드 구현에 착수하기 전, **아키텍처의 잠재적 리스크를 사전에 예방하고, 실무 관점에서 필요한 추가 제안과 보완점**을 명확히 정리하기 위해 작성되었습니다.

특히 사용자가 질문한 **"한국경제(한경) 등 언론사의 오늘의 기사 수집 가능 여부"**에 대한 기술 검증 결과와 최적 구현 방안을 포함합니다.

---

## 2. 사용자 핵심 질문 검토: "한경 같은 기사도 가능한가? (오늘의 기사)"

### 2.1 검증 결과: **완벽히 가능하며, 실제 테스트를 통해 최적 경로를 확정했습니다.**

한국경제, 매일경제, 연합뉴스 등 국내 주요 경제/일간지의 "오늘의 기사(실시간 뉴스)"를 수집하여 **Topic Discovery(주제 발굴)의 핵심 입력 소스**로 사용하는 것은 기술적으로 매우 유효합니다.

### 2.2 기술 방식 비교 및 실측 테스트 결과

| 연동 방식 | 기술 구현 | 실측 결과 및 특징 | 추천도 |
|:---|:---|:---|:---:|
| **1) Google News RSS (한경 타겟)** | `https://news.google.com/rss/search?q=site:hankyung.com` | **[실측 완료] 100건 실시간 기사 1초 만에 수집 성공**<br>• 100% 무료, API 키 불필요<br>• Cloudflare/봇 차단(403) 없음<br>• 제목, 요약, 발행시각, 원문 링크 제공 | **★ 최우선 채택 (1순위)** |
| **2) 한경 공식 RSS 직접 호출** | `https://www.hankyung.com/feed/economy` | **[실측 완료] HTTP 403 Forbidden 반환**<br>• 웹서버 차원에서 자동화 봇 User-Agent 차단<br>• 직접 호출 시 실패 위험 존재 | **비권장 (차단 리스크)** |
| **3) Google Serper News API** | Google Serper `/news` 엔드포인트 | • 구조화된 JSON 데이터 (썸네일, 언론사, 정확한 일시)<br>• 무료 크레딧(월 2,500회) 소진 시 유료 | **심층 검색 시 보조 활용** |
| **4) 웹 크롤링 (Jina / BeautifulSoup)** | 개별 기사 URL 방문 | • 본문 전체를 긁어올 때 사용<br>• 목록 수집용으로는 속도가 느림 | **본문 스크랩 단계에서만 사용** |

> **구현 확정안**:  
> `Topic Discovery` 노드에서는 Google News RSS의 `site:hankyung.com` 및 경제 키워드 피드를 활용하여 **100% 무료·초고속·차단 없이 오늘의 한경 최신 기사 50~100건을 1초 만에 확보**합니다.

## 3. 구현 전 7대 핵심 보완 제안 (Architectural Improvements)

기존 설계서를 정밀 검토하여 도출한 **7가지 필수 보완점과 해결책**입니다.

---

### 제안 1. 검색 엔진의 "한국어/최신 시사" 품질 한계 보완 (DuckDuckGo vs Serper)

- **문제점**:
  DuckDuckGo(DDG)는 무료이고 간편하지만, **한국어 최신 경제/산업 시사 키워드에 대해 검색 결과 누락 및 품질 저하**가 빈번합니다.
- **보완책**:
  1. **Topic Discovery 단계**: 포털 검색 대신 **한경/구글뉴스 RSS 피드**를 메인 데이터소스로 고정하여 속도와 한국어 최신성을 보장합니다.
  2. **DLS Research 단계**:
     - `SERPER_API_KEY`가 환경변수에 있으면 Google Serper(`hl=ko, gl=kr`)를 최우선 엔진으로 사용합니다.
     - 키가 없을 때만 DuckDuckGo(`kr-kr`)로 자동 fallback합니다.
     - `config/settings.yaml`에서 엔진 우선순위를 언제든 변경할 수 있는 **Provider Factory 패턴**을 적용합니다.

---

### 제안 2. 본문 크롤링 봇 차단(Paywall/Cloudflare) 3단계 Fallback 전략

- **문제점**:
  한경, 외신(블룸버그, FT), 네이버 프리미엄 콘텐츠 등은 Jina Reader로 크롤링할 때 403/503 에러나 구독 결제창(Paywall)으로 인해 본문이 비어있을 수 있습니다.
- **보완책 (3단계 Fallback 파이프라인)**:
  ```
  [크롤링 요청 URL]
         │
         ▼
  [1단계: Jina Reader (r.jina.ai)] ─── 성공 ───► [본문 획득]
         │ (실패 / 차단 / 내용 부실)
         ▼
  [2단계: 로컬 파서 Trafilatura / BeautifulSoup] ─── 성공 ───► [본문 획득]
         │ (실패 / Paywall)
         ▼
  [3단계: 검색 엔진 스니펫 Fallback] ───► [검색 결과 요약문 활용]
  ```
  - 특정 기사 크롤링이 실패하더라도 에이전트 리서치 전체가 중단되지 않고 다음 기사나 검색 요약문을 활용해 계속 진행되도록 안전장치를 둡니다.

---

### 제안 3. LangGraph State 메모리 누수 & 토큰 폭증 방지 (Context Memory Management)

- **문제점**:
  섹션이 5개이고 각 섹션마다 3회 루프 × 3개 URL을 크롤링하면 수십 개의 긴 본문(HTML/마크다운)이 State에 누적됩니다.
  이로 인해 후반부 노드 실행 시 **LLM 컨텍스트 윈도우가 50,000~100,000 토큰으로 비대화되어 속도 저하, API 비용 폭증, LLM 환각(Lost in the middle)** 현상이 일어납니다.
- **보완책 (Key Evidence Extraction 패턴)**:
  - 크롤링 직후 원문 전체(1만 자)를 State에 영구 보관하지 않습니다.
  - `scraper` 노드에서 해당 섹션의 소주제와 직결된 **핵심 사실/통계/인용구(Key Evidence: 500~1,000자 내외)**만 추출하여 State의 `scraped_content`에 전달합니다.
  - 원문 전문은 디스크 임시 디렉토리(`temp/{run_id}/raw_pages/`)에만 백업 보관합니다.

---

### 제안 4. LLM 모델 계층화(Tiering) 및 Rate Limit 방어

- **문제점**:
  모든 노드에 고비용/대형 LLM을 쓰면 비용이 급증하며, 반대로 Free Tier 사용 시 분당/일일 호출 횟수 제한(Rate Limit / 429 RESOURCE_EXHAUSTED)이 발생할 수 있습니다.
- **보완책**:
  역할별로 모델 티어를 3단계로 분리합니다:

| 티어 (Tier) | 담당 노드 | 권장 모델 | 특성 |
|:---|:---|:---|:---|
| **Fast Tier** | `query_generator`, `reflector` | Gemini 2.5 Flash / Flash-Lite / Ollama 8B | 1초 이내 초고속 응답, JSON 포맷 준수, 최저 비용 |
| **Standard Tier** | `topic_discovery`, `outline_generator` | Gemini 2.5 Flash / GPT-4o-mini | 아이디어 기획 및 체계적 목차 구성 능력 |
| **Deep Tier** | `synthesizer`, `assembler` | Gemini 2.5 Pro / Claude 3.5 Sonnet | 깊이 있는 문장력, 맥락 종합, 장문 리포트 집필 |

- **재시도(Retry) 및 Fallback**:
  - LLM 호출 시 지수 백오프(Exponential Backoff)를 적용하고, 429 오류 발생 시 백업 모델로 자동 전환하도록 래핑합니다.

---

### 제안 5. Human-in-the-loop: 대화형 CLI 인터랙터 구현

- **문제점**:
  LangGraph의 `interrupt()`는 상태를 일시정지하지만, 사용자가 터미널(CLI) 환경에서 어떻게 입력을 주어 재개(`resume`)하는지 실행 스크립트가 직관적이어야 합니다.
- **보완책**:
  - `src/main.py`에 직관적인 대화형 CLI 인터랙터 구현:
    1. **주제 발굴 시**: 터미널에 오늘자 한경 기사 기반 5대 추천 주제를 깔끔하게 출력 → `번호 선택 [1-5] 또는 직접 입력:`
    2. **아웃라인 생성 시**: 터미널에 3개 후보 아웃라인(A, B, C안)을 마크다운 표/목차로 출력 → `[1] A안 승인 [2] B안 승인 [3] C안 승인 [e] 직접 수정 [r] 재생성:`
    3. 선택 즉시 `graph.invoke(Command(resume=...))`로 끊김 없이 DLS 심층 리서치로 자동 전환.

---

### 제안 6. 출처(Citation) 표기 및 팩트 신뢰성 강화

- **문제점**:
  AI가 작성한 보고서는 출처 링크가 모호하면 신뢰도가 떨어집니다.
- **보완책**:
  - 본문 서술 시 인용한 핵심 데이터/주장에 각주 번호(`[1]`, `[2]`)를 부여.
  - 최종 리포트 하단에 **[참고문헌 및 데이터 출처]** 테이블을 자동 생성:
    - 번호, 기사/페이지 제목, 언론사(한국경제 등), URL 링크, 수집 시각

---

### 제안 7. 섹션 단위 에러 격리 (Fault Isolation)

- **문제점**:
  아웃라인이 5개 섹션으로 구성되었을 때, 3번째 섹션의 검색/크롤링에서 일시적 네트워크 장애가 발생하면 전체 리서치가 죽을 위험이 있습니다.
- **보완책**:
  - 각 섹션의 리서치 루프를 `try-except`로 격리하여, 특정 섹션이 실패하더라도 "데이터 수집 부족" 알림과 함께 가용한 데이터만으로 초안을 작성하고 나머지 4개 섹션은 정상 완료되도록 보장합니다.

### 제안 8. 편향 방지를 위한 '균형 쿼리(Balanced Querying)' 강제 생성

- **문제점**:
  특정 기업이나 기술(예: 특정 주식 종목, 신기술 트렌드)을 리서치할 때 긍정적인 기사만 검색되어 **장밋빛 전망 일색의 편향된 보고서**가 작성될 위험이 있습니다.
- **보완책**:
  - `query_generator` 프롬프트에 **"비판적/리스크 쿼리 1개 이상 필수 포함"** 규칙을 부여합니다.
    - 예: `["AI 데이터센터 전력 수요 현황", "AI 데이터센터 수혜 기업 실적", "AI 데이터센터 전력망 병목 현상 및 투자 지연 리스크"]`
  - 이를 통해 찬반 양론과 리스크 요인이 균형 있게 다뤄지는 고품질 보고서를 보장합니다.

---

### 제안 9. 로컬 캐싱(Local Caching) 계층 도입으로 비용 및 지연시간 90% 절감

- **문제점**:
  리포트 작성 중 오류로 재실행하거나, 유사한 주제를 연속 리서치할 때 동일한 기사 URL과 동일한 검색 쿼리를 반복 호출하여 불필요한 API 쿼터 소모와 10~20초의 지연이 발생합니다.
- **보완책**:
  - `temp/cache/` 디렉토리에 SQLite 또는 파일 기반 경량 캐시 도입:
    - **Search Cache**: 검색 쿼리 해시 기준 24시간 유효.
    - **Scrape Cache**: 기사 URL 기준 7일 유효.
  - 캐시 히트 시 네트워크 호출 없이 즉각(0.01초) 반환하여 리서치 반복 테스트 속도를 대폭 향상합니다.

---

### 제안 10. 경제/산업 기사 특화: 정량 수치/통계(Quantitative Data) 표 자동 추출

- **문제점**:
  한국경제 등 경제지의 기사는 **숫자(매출액, 영업이익률, 시장 점유율, 전년 대비 증감율)**가 핵심 팩트인데, 줄글로만 요약하면 가독성이 떨어집니다.
- **보완책**:
  - `synthesizer` 노드 프롬프트에 기사 본문에 포함된 **핵심 정량 수치와 통계를 발췌하여 마크다운 표(Table)로 반드시 포함**하도록 지침을 추가합니다.

---

### 제안 11. Notion MCP 연동 지원 (원클릭 리포트 발행)

- **문제점**:
  로컬 마크다운 파일(`.md`)로만 저장되면 모바일이나 동료들과 공유하기 번거롭습니다.
- **보완책**:
  - 이미 IDE 환경에 연동되어 있는 `notion-mcp-server`를 활용할 수 있도록 최종 리포트 출력 시 **"Notion 페이지로 즉시 내보내기"** 옵션을 옵셔널 노드로 설계에 반영합니다.
