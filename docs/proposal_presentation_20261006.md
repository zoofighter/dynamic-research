## 📌 1. 제안 개요 (Executive Summary)

현대 기업 환경에서 반도체, 인공지능, 배터리 등 핵심 첨단 기술과 글로벌 공급망 이슈는 매일 시시각각 급변합니다. 그러나 전통적인 사내 검색 및 기존 RAG(Retrieval-Augmented Generation) 시스템은 **사전 벡터 DB 구축 지연으로 인한 '시점 단절', 인간의 의도가 배제된 '일방향 자동화의 실패', 그리고 원문 검증이 불가능한 '환각(Hallucination)'**이라는 3대 고질적 병목을 안고 있습니다.

본 제안은 사전 벡터 DB 없이 실시간 라이브 웹을 자율 탐색·크롤링·검증하는 **Dynamic Live Search (DLS)** 엔진과 인간이 리서치 방향타를 잡는 **Human-in-the-Loop (HITL)** 거버넌스를 결합한 **차세대 자율 심층 리서치 AI 플랫폼**의 구축을 제안합니다.

특히 본 제안서에는 CLI 환경뿐 아니라 실제 현업 실무진이 매일 접속해 활용하는 **Streamlit 웹 애플리케이션(DLS Deep Research Studio)의 핵심 4대 UI 화면(토픽 발굴, 리서치 콘솔, 번들 열람실, 스마트 Q&A)**을 슬라이드 내 고해상도 브라우저 목업과 함께 수록하여 직관적인 플랫폼 도입 효과를 증명합니다.

### 🌟 3대 핵심 도입 효과 (Core ROI)
1. **리서치 소요 시간 95% 단축 (72시간 ➔ 10분)**: 며칠씩 걸리던 시장·기술 리서치 및 보고서 작성 업무를 10분 이내로 단축.
2. **운영 토큰 비용 0원화**: OpenCode Meta Muse Spark 1.3 무료 LLM 기본 탑재 및 스마트 캐싱으로 엔터프라이즈 API 비용 제로 달성.
3. **100% 출처 매핑 & 4대 맞춤형 번들 보고서 동시 산출**: 단 1회 리서치로 경영진 전략 브리프(1-Pager), 심층 기술 분석서, 경쟁사 비교 매트릭스, 리스크 실사 체크리스트를 자동 패키징.

### [Slide 2] 추진 배경 및 현업 리서치의 3대 페인포인트 (Pain Points)
- **슬라이드 목적**: 기존 RAG 및 수작업 리서치의 치명적 결함을 명확히 규명하여 신규 플랫폼 도입의 시급성 설득
- **3대 페인포인트 카드 레이아웃**:
  1. **PAIN POINT 01. 사전 임베딩(RAG)의 시점 한계**
     - 벡터 DB 구축, 청킹, 임베딩 파이프라인 지연 발생으로 과거 데이터 고착
     - 엔비디아, 삼성전자, SK하이닉스의 실시간 수율/공시/계약 속보 대응 불가
     - 고정된 지식 창고에 갇혀 실시간 웹의 최신 1차 보도를 놓침
  2. **PAIN POINT 02. 맹목적 전면 자동화의 실패**
     - 인간의 비즈니스 의도와 관점(Angle)이 배제된 일방적 보고서 출력으로 폐기율 급증
     - 목차(Outline) 기획 단계에서 방향타를 잡지 못하면 수백 건 검색도 무용지물
     - 경영진이 검증하려는 핵심 질문을 주입할 Human-in-the-Loop 거버넌스 부재
  3. **PAIN POINT 03. 출처 불투명성 & 환각(Hallucination)**
     - 포털/블로그 요약문은 출처 원문 URL과 대조 검증이 원천 불가
     - 확인된 팩트(Fact)와 AI 주관적 해석(Analysis)이 뒤섞여 비즈니스 의사결정 리스크 초래
     - 기사 간 상충점이나 과장 보도를 걸러낼 자율 검증 및 체크리스트 결여

### [Slide 3] 사업 목표 및 기대 효과 (Quantitative & Qualitative ROI)
- **슬라이드 목적**: 정량적 KPI와 As-Is vs To-Be 명확한 대조를 통한 투자 타당성 입증
- **상단 3대 핵심 정량 지표**:
  - **`95% ↓` 리서치 리드타임 획기적 단축**: 3일(72시간) 소요되던 자료 조사·분석·보고서 작성을 단 10분 만에 완성
  - **`0원` 토큰 비용 0원화**: OpenCode Meta Muse Spark 무료 LLM 통합 및 스마트 디스크 캐싱으로 API 비용 제로 달성
  - **`100%` 근거 투명성 (1:1 인라인 각주)**: 모든 문장에 원문 기사 인라인 각주(`[^1]`) 매핑 및 미확인 주장 검증표 분리
- **하단 비교 패널 (As-Is vs To-Be)**:
  - **기존 방식 (As-Is)**: 포털 수작업 검색, 메모장 복사·붙여넣기, RAG 벡터 DB 고비용 유지, 단일 장문 리포트 재가공 피로, 환각 검증을 위해 사람이 다시 검색하는 역설
  - **플랫폼 도입 후 (To-Be)**: 실시간 뉴스 스캔으로 오늘자 핫 토픽 추천 및 다각도 목차(A/B/C/D) 즉시 생성, Zero-VectorDB 1초 100건 수집, 1회 리서치로 4종 맞춤 번들 보고서 동시 획득, C-Level 직보 가능한 최고 신뢰도 보장

### [Slide 4] 핵심 솔루션: Dynamic Live Search (DLS) 패러다임 전환
- **슬라이드 목적**: 기술 세대교체(Generational Shift) 관점의 아키텍처 우위 제시
- **3대 패러다임 비교**:
  1. **1세대 RAG (전통적 방식)**: 사내 PDF·위키 사전 저장 문서 대상, 임베딩 시점 이전 데이터만 조회 가능, 유지비 과다, 급변 이슈 대응 불가
  2. **2세대 Agentic RAG**: 복수 벡터 DB 및 웹 검색 도구 혼용, 여전히 캐시 및 사전 DB 종속적, API 비용 폭증, 심층 분석 리포트 한계
  3. **3세대 Dynamic Live Search (본 제안)**: **100% 실시간 뉴스 RSS + 개방형 라이브 웹 원문 직접 탐색**, Zero Pre-indexing, Vector DB 불필요, 질문 분해 ➔ 듀얼 수집 ➔ 자율 반성(Reflection) ➔ 4종 번들 패키징

### [Slide 5] 시스템 아키텍처: 2-Agent 분리 거버넌스 & Human-in-the-Loop
- **슬라이드 목적**: 안전성과 효율성을 극대화한 LangGraph 기반 느슨한 결합(Loose Coupling) 구조 설명
- **2대 독립 파이프라인**:
  - **Stage 1. 기획 & 목차 확정 (`TopicOutlineGraph`)**:
    - Google News RSS 실시간 100건 헤드라인 스캔
    - LLM 트렌드 클러스터링으로 작성 가치 높은 핫 토픽 Top 5 도출
    - 독자 관점별 다각도 목차(A/B/C/D) 및 핵심 질문 기획
    - **Human Review (HITL)**: 사용자가 웹 UI 또는 터미널에서 선택·수정·승인
    - 표준 인터페이스 파일: `approved_outline.json` 규격 저장 후 안전한 핸드오프
  - **Stage 2. 자율 심층 리서치 (`DLSResearchGraph`)**:
    - 3대 전략 쿼리 분해 (국내 팩트, 해외 테크, 기업 IR, 편향방지 리스크 쿼리)
    - 듀얼 뉴스 병렬 동시 수집 (DuckDuckGo News + Google RSS 교차 병합)
    - Trafilatura / Jina Reader로 순수 본문 마크다운 파싱
    - **자율 반성 (Self-Reflection)**: 팩트 충분성 자체 평가 및 부족 시 재검색 루프
    - 다각화 리포트 번들 합성 및 `output/bundles/` 최종 패키징

### [Slide 6] 핵심 차별화 기술 역량 (4 Key Differentiating Features)
- **슬라이드 목적**: 경쟁 솔루션이 모방하기 어려운 4대 고유 엔지니어링 역량 부각
- **2x2 그리드 구성**:
  1. **뉴스 전용 듀얼 수집기 (Dual News Collector)**: Google News RSS (`site:hankyung.com` 등 타겟) + DuckDuckGo News 병렬 실행, 봇 차단(403) 우회, 1초 100건 수집 및 제도권 1차 보도 위주 인터리빙 교차 병합
  2. **순수 본문 마크다운 추출기 (Trafilatura + Jina Reader)**: 배너, 메뉴, 광고를 완벽 배제하고 순수 기사 본문만 추출, 로컬 우선 + 클라우드 백업의 2단계 Fallback 무중단 보장
  3. **100% 무료 LLM 탑재 (OpenCode Muse Spark)**: Meta Muse Spark 1.3 무료 모델을 기본 채택하여 API 과금 완전 제로화, 로컬 REST API 실시간 포트 자동 감지 및 CLI Fallback, Google Gemini / Groq / Ollama 플러그인 지원
  4. **자율 반성 (Self-Reflection) & 편향 방지**: 비판/수율/리스크 쿼리 강제 생성, 팩트 충분성 자체 채점 및 재검색 루프, 팩트(Fact)-해석(Analysis)-미확인(Unverified) 3분할 서술

### [Slide 7] 주요 산출물: 다각화 전문 보고서 패키지 (Multi-Tier Report Bundle)
- **슬라이드 목적**: 단 1회의 리서치 자원으로 전사 이해관계자 모두를 만족시키는 산출물 체계 증명
- **4대 전문 보고서 사양**:
  1. **Report 01. 경영진 전략 브리프 (Executive 1-Pager)**: C-Level용, A4 1~2페이지, 3줄 결론 (TL;DR), 핵심 정량 KPI 카드 3~4개, 즉시 실행 과제
  2. **Report 02. 심층 기술·산업 상세 보고서 (Technical Deep-Dive)**: R&D 엔지니어용, 10~20페이지, 질문 정의, 문장별 1:1 인라인 각주(`[^1]`), 아키텍처/공정 상세
  3. **Report 03. 경쟁사 벤치마크 매트릭스 (Competitive Benchmark Matrix)**: 사업기획·전략팀용, 3~5페이지, 4대 축 비교표(스펙, 생산 Capa, 수율, 가격), 기업별 경쟁 우위/열위
  4. **Report 04. 리스크 진단 & 실사 과제서 (Risk & Due-Diligence Checklist)**: 리스크 관리·투자 심사역용, 2~4페이지, 상충 보도 평가, 미확인 루머 vs 확인 팩트 분리 표
- *(특화 포맷 확장)*: 한국경제 탐사보도 기사 포맷, 월가 주식 리서치(Wall Street Equity Research) 포맷 추가 지원
