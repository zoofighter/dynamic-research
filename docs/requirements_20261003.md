# 요건정의서 — 자율 리서치 Agent (Dynamic Research)

> **작성일**: 2026-10-03  
> **문서 버전**: v1.0  
> **프로젝트 경로**: `c_1003_dyanmic_research`

---

## 1. 시스템 개요

### 1.1 목적
사람이 주제와 아웃라인(질문 + 결론)을 설계하면, AI 에이전트가 **Dynamic Live Search**를 통해 실시간 웹 검색·크롤링·합성을 수행하여 아웃라인의 각 슬롯을 자동으로 채우고 최종 마크다운 리포트를 생성하는 **자율 리서치 시스템**.

### 1.2 핵심 설계 원칙
- **선택형 아키텍처**: 검색 방식, LLM, 파서 등 주요 컴포넌트를 사용자가 **런타임에 선택**할 수 있도록 플러그인 구조로 설계
- **Human-in-the-Loop (HITL)**: 에이전트가 제안하고 사람이 승인·선택하는 협업 방식
- **오케스트레이션**: **LangGraph** 기반으로 구현

## 2. 에이전트 구성

### 2.1 에이전트 목록

| # | 에이전트 | 역할 | 비고 |
|:---:|:---|:---|:---|
| 1 | **Outline Proposer Agent** | 주제를 기반으로 아웃라인(질문·결론) 초안을 **제안** | 사람이 최종 선택·수정 |
| 2 | **Query Generator Agent** | 승인된 아웃라인의 각 항목에 대해 다중 검색 쿼리를 동적 생성 | 항목당 3~4개 쿼리 |
| 3 | **Search Agent** | 생성된 쿼리로 실시간 웹 검색 수행 | 검색 엔진 선택 가능 |
| 4 | **Scraper Agent** | 검색 결과 URL의 웹페이지 원문을 마크다운으로 추출 | 파서 선택 가능 |
| 5 | **Reflection Agent** | 수집된 정보의 충분성을 자율 평가, 부족 시 Sub-Query 생성 | 2~3회 재귀 루프 |
| 6 | **Synthesizer Agent** | 팩트/해석을 분리하고 출처 각주를 매핑하여 최종 리포트 합성 | 저장 규격 준수 |

### 2.2 에이전트 흐름도

```
[Outline Proposer Agent]
        ↓ 아웃라인 초안 제안
    (Human 선택·수정·승인)
        ↓
[Query Generator Agent]
        ↓ 검색 쿼리 생성
[Search Agent]
        ↓ 검색 결과 (URL 목록)
[Scraper Agent]
        ↓ 웹페이지 원문 마크다운 → temp/ 에 저장
[Reflection Agent]
        ↓ 정보 충분성 평가
       ╱ ╲
  부족 → Query Generator로 재귀    충분 →
                                        ↓
                              [Synthesizer Agent]
                                        ↓
                              최종 마크다운 리포트 출력
```

## 3. 기능 요건 (Functional Requirements)

### FR-01. 아웃라인 제안 및 선택

| 항목 | 내용 |
|:---|:---|
| **설명** | 사용자가 주제를 입력하면 Outline Proposer Agent가 아웃라인(섹션·질문·결론) 초안을 복수 제안 |
| **입력** | 주제 키워드 또는 문장 |
| **출력** | 아웃라인 초안 (복수 안) |
| **사용자 행동** | 초안 중 하나를 선택하거나 직접 수정·작성 후 승인 |

### FR-02. 동적 쿼리 생성 (Query Generation)

| 항목 | 내용 |
|:---|:---|
| **설명** | 승인된 아웃라인의 각 섹션/질문별로 전문 검색 쿼리를 자동 생성 |
| **입력** | 승인된 아웃라인 + 주제 컨텍스트 |
| **출력** | 섹션당 3~4개의 검색 쿼리 |
| **요구사항** | 복합 질문을 다각도로 분해, 영어/한국어 혼합 쿼리 지원 |

### FR-03. 실시간 웹 검색 (Dynamic Live Search)

| 항목 | 내용 |
|:---|:---|
| **설명** | 생성된 쿼리로 실시간 웹 검색 수행 |
| **검색 엔진 옵션** | 사용자가 선택 가능 (아래 중 택1 또는 조합) |
| | • Tavily Search API |
| | • Exa.ai |
| | • Google / Serper API |
| | • 무료 API 또는 직접 구현한 검색 모듈 |
| **출력** | 쿼리별 상위 10~20개 URL + 스니펫 |

### FR-04. 웹페이지 크롤링 및 마크다운 추출

| 항목 | 내용 |
|:---|:---|
| **설명** | 검색 결과 URL의 웹페이지를 방문하여 본문 전체를 순수 마크다운으로 추출 |
| **파서 옵션** | 사용자가 선택 가능 |
| | • Jina Reader (`r.jina.ai`) |
| | • Crawl4AI |
| **출력** | 광고·네비게이션 제거된 순수 마크다운 텍스트 |
| **저장** | 크롤링 결과물을 **`temp/` 디렉토리에 중간 저장** |

### FR-05. 자기반성 및 재귀 검색 (Self-Reflection Loop)

| 항목 | 내용 |
|:---|:---|
| **설명** | 수집된 정보가 아웃라인 슬롯을 채우기에 충분한지 자율 평가 |
| **부족 시** | 정보 갭을 식별하고 Sub-Query를 생성하여 FR-02 ~ FR-04를 재귀 수행 |
| **루프 제한** | 최대 2~3회 |
| **출력** | 충분성 판단 결과 + 수집된 전체 Evidence 목록 |

### FR-06. 리포트 합성 및 저장

| 항목 | 내용 |
|:---|:---|
| **설명** | 수집된 Evidence를 기반으로 아웃라인 슬롯을 채우고 최종 마크다운 리포트 생성 |
| **저장 규격** | 아래 5대 핵심 요소 준수 (섹션 5 참조) |
| **출력** | 최종 `.md` 리포트 파일 |

### FR-07. LLM 선택

| 항목 | 내용 |
|:---|:---|
| **설명** | 쿼리 생성, 반성, 합성 등에 사용할 LLM을 사용자가 선택 가능 |
| **옵션** | Gemini, GPT, Claude 등 (구현 시 확장 가능한 인터페이스) |

## 4. 비기능 요건 (Non-Functional Requirements)

### NFR-01. 모듈 교체 가능성 (Pluggability)

| 항목 | 내용 |
|:---|:---|
| **설명** | 검색 엔진, 웹 파서, LLM을 런타임 설정으로 교체 가능 |
| **구현 방식** | 각 컴포넌트를 추상 인터페이스로 정의, 구체 구현체를 설정 파일 또는 CLI 인자로 주입 |

### NFR-02. 중간 데이터 보존

| 항목 | 내용 |
|:---|:---|
| **설명** | Dynamic Live Search 과정의 중간 결과물(크롤링 원문, 검색 결과 등)을 `temp/` 폴더에 저장 |
| **목적** | 디버깅, 재실행 시 크롤링 비용 절감, 데이터 추적성 확보 |

### NFR-03. 지연시간 허용

| 항목 | 내용 |
|:---|:---|
| **설명** | 검색→크롤링→합성에 10~25초 소요 허용 |
| **운영 방식** | 실시간 채팅이 아닌 비동기 배치 리포트 생성 방식 |

### NFR-04. 오류 처리

| 항목 | 내용 |
|:---|:---|
| **페이월 차단** | 유료 매체 크롤링 실패 시 오픈 1차 출처(SEC, IR, Press Release) 우선 타겟팅 |

| **검색 결과 부재** | 쿼리 재구성 또는 검색 엔진 변경 시도 |

## 5. 리포트 저장 규격 (5대 핵심 요소)

최종 `.md` 리포트에 반드시 포함해야 할 품질 기준:

### ① 원본 출처 투명성
- Frontmatter에 `search_metadata.search_queries` 기록
- 본문 핵심 수치에 `[^1]`, `[^2]` 인라인 각주 매핑
- 1차 출처(공시, IR, 논문) / 2차 출처(미디어, 리포트) 구분

### ② 사실 vs 해석 분리
각 섹션마다 3분할 슬롯 유지:
- `확인된 사실 (Facts)` — 날짜, 수치, 원문 팩트
- `에이전트 해석 (Analysis)` — 팩트로부터 도출한 시사점
- `미확인 주장 (Unverified)` — 교차 검증 미완료 추정치

### ③ 반대 근거 & 반증 조건
- Core Thesis와 대치되는 데이터를 별도 섹션에 수록
- 결론 철회·수정 기준을 사전 정의 (예: "수율 X% 미달 시 결론 수정")

### ④ 휴먼 검토 슬롯 (HITL Callout)
- `> [!NOTE] 휴먼 피드백 & 직접 집필란` Callout 영역 배치
- 아웃라인 승인 체크박스, 전문가 인사이트 작성란 제공

### ⑤ 옵시디언 위키링크 연결
- `[[기존_문서]]` 양방향 링크 자동 연결
- MOC(Map of Content) 및 태그 체계 수록

├── output/                     ← 최종 리포트 출력
├── docs/                       ← 기획 문서

## 8. 용어 정의

| 용어 | 정의 |
|:---|:---|
| **Dynamic Live Search** | 사전 벡터 DB 없이, 질문 시점에 실시간으로 웹을 검색·크롤링·합성하는 에이전틱 리서치 패러다임 |
| **아웃라인 (Outline)** | 리서치 리포트의 섹션 구조. 각 섹션은 질문(Question)과 기대 결론(Thesis)으로 구성 |
| **슬롯 채우기 (Slot-filling)** | 아웃라인의 빈 섹션에 검색·크롤링으로 수집한 Evidence를 삽입하는 행위 |
| **Self-Reflection** | 에이전트가 수집 정보의 충분성을 자율 평가하고 부족 시 재검색하는 재귀 루프 |
| **HITL** | Human-in-the-Loop. 에이전트가 제안하고 사람이 검토·승인·수정하는 협업 방식 |
| **Provider** | 검색엔진/파서/LLM 등 교체 가능한 외부 서비스 구현체 |
