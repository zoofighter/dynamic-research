## 1. 개요 (Executive Summary)

DLS(Dynamic Learning System) 플랫폼의 **"📊 3. A/B 엔진 벤치마크"**는 **"수집된 대규모 뉴스 웹 문서를 AI 모델에 어떻게 주입해야 가장 빠르고, 정확하며, 거짓말(환각) 없이 정밀한 팩트를 추출할 수 있는가?"**를 실시간 데이터로 계량 검증하는 성능 평가 체계입니다.

본 문서는 프롬프트 스터핑(Prompt Stuffing) 방식과 LlamaIndex 기반 문장 단위 청킹/재순위화 방식의 구조적 차이점, 실측 벤치마크 지표, 그리고 전체 리서치 시스템 관점에서의 전략적 도입 가치를 정의합니다.

## 3. A/B 벤치마크가 갖는 4대 핵심 기술 가치

### ① '중간 정보 유실(Lost in the Middle)' 현상의 원천 차단
- 거대언어모델(LLM)은 입력 프롬프트가 길어질수록 글의 시작과 끝부분에만 주의를 기울이고, **문서 중앙부에 위치한 핵심 일정, 수치, 수율, 가격 데이터를 간과하거나 망각하는 고질적인 인지 편향(Lost in the Middle)**을 보입니다.
- Baseline은 3~5개 기사의 사족과 노이즈가 모두 섞여 핵심 수치가 묻힐 위험이 높습니다.
- 반면 LlamaIndex 엔진은 질문과 직접 관련된 핵심 문장 노드만을 엄선하여 주입하므로, **정보 손실 없이 팩트 회수율(Recall)을 극대화**합니다.

### ② 추론 지연 시간(TTFT & Latency)의 2배 단축
- LLM의 첫 토큰 생성 시간(Time to First Token)과 전체 생성 속도는 입력 토큰 길이에 정비례하여 증가합니다.
- LlamaIndex 엔진은 불필요한 광고 문구, 저작권 문구, 기자 연락처 등을 65% 이상 사전 필터링하여 전달하므로, **동일한 LLM 모델에서도 응답 대기 시간을 25초에서 13초로 단축**시킵니다.

### ③ 환각(Hallucination) 억제 및 문장 단위 추적성(Traceability)
- 벤치마크 질의였던 *"삼성전자 HBM4의 엔비디아 납품 팩트는?"*에 대해 실제 수집된 기사에는 구체적인 엔비디아 납품 승인 계약 내용이 없었습니다.
- 이때 고순도 문장만 전달받은 LlamaIndex 엔진은 없는 사실을 임의로 지어내지 않고, **"선별된 발췌 데이터 내에는 엔비디아 납품 승인·물량·시점에 대한 직접적 팩트가 없으며, 주요 고객사 샘플 공급 언급만 확인된다"**고 명확히 한계를 선언했습니다.
- 문장 노드마다 출처 URL 메타데이터가 1:1 보존되므로 `[^1]`, `[^2]` 각주의 진위 여부를 클릭 한 번으로 즉시 검증할 수 있습니다.

### ④ 상용 LLM 도입 시 경제적 비용 최적화 (ROI)
- 현재 DLS 시스템은 토큰 비용이 0원인 OpenCode Muse Spark를 기본 엔진으로 운영하고 있어 비용 부담이 없습니다.
- 그러나 향후 금융·기업 실무용으로 고가의 상용 모델(예: GPT-4o, Claude 3.5 Sonnet, Gemini 1.5 Pro)을 도입할 경우, **LlamaIndex 엔진은 입력 토큰 비용을 65% 이상 절감하여 API 운영 비용을 1/3 수준으로 대폭 절약**해 주는 경제적 가치를 가집니다.

## 4. 전체 DLS 시스템에서의 실무적 활용 방안

1. **파이프라인 엔진 채택의 정량적 근거**:
   - DLS 자율 심층 리서치에서 왜 단순 프롬프트 주입이 아닌 **LlamaIndex 기반 문장 단위 분할/선별 엔진을 기본 표준으로 채택해야 하는지**에 대한 객관적 증거를 제공합니다.
2. **도메인별 품질 스트레스 테스트**:
   - 반도체, AI 소프트웨어, 금융, 바이오 등 새로운 도메인의 기사가 수집되었을 때, 두 방식 간의 정보 압축률과 팩트 정밀도를 즉석에서 A/B 비교하여 시스템 안정성을 점검할 수 있습니다.
3. **지속 가능한 리서치 에이전트 품질 관리**:
   - LLM 모델이나 프롬프트 구조가 변경되었을 때 회귀 테스트(Regression Test) 벤치마크로 활용하여 응답 품질 저하 여부를 감시합니다.
